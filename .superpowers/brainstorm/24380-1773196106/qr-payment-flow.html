QR Code Contents

The QR encodes a URL with signed parameters:
https://[app-url]/pay?token=eyJhbGciOiJIUzI1NiJ9...
Token payload (JWT-signed to prevent tampering):
{
"inv": "INV-2026-03-00042",
"con": "ALC-2024-00123",
"acct": "CUST-0017",
"amt": 285000.00,
"bal": 285000.00,
"due": "2026-03-15",
"exp": 1773800000
}
JWT signed with server secret — prevents URL parameter tampering. Includes expiry for security.

Payment Flow Details
Credit/Debit Card (Stripe)
1. Create PaymentIntent on server
2. Stripe Elements renders card input
3. Client confirms payment
4. Webhook confirms → update invoice balance
5. Show success screen with receipt
BPI Bank Transfer (Emulated)
1. Show BPI account details to transfer to
2. Customer transfers externally
3. Customer uploads proof-of-payment
4. OCR extracts details from receipt
5. AI validates → creates incoming payment
6. If mismatch → escalation created
Partial Payment
1. Customer toggles "Pay Partial"
2. Editable amount field appears
3. Payment recorded for partial amount
4. Invoice balance_remaining decremented
5. Invoice status → PARTIAL
6. New QR generated for remaining balance
QR Generation
Library: qrcode (npm)
Renders as SVG/PNG in emulator
Scannable by any phone camera
JWT-signed URL prevents tampering
Expires after configurable window
